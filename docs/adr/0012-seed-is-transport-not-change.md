# ADR-0012: A Seed is transport, not a change

Status: Accepted. Amends ADR-0004.

A **Seed** is a portable serialisation of a whole Corpus. Loading one establishes or replaces Corpus
state; exporting one writes that state back out. Seeds are how a Corpus is bootstrapped, moved
between environments, backed up, and set up for tests. The same mechanism serves testing and
production.

ADR-0004 stated that an import is a proposal like any other. That was wrong, and this decision
replaces that sentence.

## Why the original position failed

A Seed load is not a set of changes; it is the arrival of a state. Recording it as one Fact Version
per Fact would produce thousands of change events that describe no decision anyone made, and every
re-load would emit another wave of them. The audit trail — the thing this product exists to protect —
would be dominated by noise generated by its own tooling, and a genuine change would become
impossible to find.

The mistake was conflating two different questions: *what path may write?* and *at what granularity is
a write recorded?* Only the second was ever in dispute.

## The decision

The Door remains the single write path (LAW-002 is unchanged). It accepts two operations:

| Operation | Input | Recorded as |
| --- | --- | --- |
| **Propose** | a Change Request | one Fact Version per changed Fact |
| **Load** | a Seed | exactly one **Genesis** record |

A Genesis record carries the Seed's content digest, the Fact count, the actor, and the time. It does
not carry per-Fact events and never will.

Loading is atomic: the Corpus is wholly the prior state or wholly the new one.

## Why a Genesis record at all

Recording nothing would be simpler and is rejected. Without it, no one can answer where a Corpus
state came from, which is LAW-009 and is the basis on which anyone trusts a readiness score. One row
per load is not the noise this ADR exists to prevent; one row per Fact is.

## Guarding against destructive re-load

A Seed load replaces state, so an unguarded re-sync would silently destroy work committed through the
Door since the last load. Therefore:

- Loading into an **empty** Corpus proceeds.
- Loading into a Corpus with **no Change Requests since its last Genesis** proceeds; nothing is lost.
- Loading into a **diverged** Corpus is refused unless explicitly forced, and a force must be preceded
  by a preview naming what would be discarded.
- A load whose digest matches the current Genesis is a no-op, so repeated syncs are idempotent.

Automatic scheduled loading into a diverged Corpus is never permitted, forced or otherwise. A machine
may not discard human decisions on a timer.

## Consequences

- Seed export is bidirectional and doubles as the backup mechanism that ADR-0003 left owed.
- Seed format is the Corpus's portability contract and must be versioned.
- A Seed is a technical artifact. It is never a business-facing surface (LAW-010).
